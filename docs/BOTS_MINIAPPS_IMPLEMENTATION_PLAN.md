# 🤖 План реализации Ботов и Мини-приложений (как в Telegram) — встроенная фича HanWe

## 🎯 Визия и цели

**Цель:** Сделать ботов и мини-приложения **нативной возможностью HanWe**, чтобы пользователи могли создавать и использовать ботов прямо внутри приложения — точно так же, как в Telegram через @BotFather.

HanWe становится не просто мессенджером и лентой, а **платформой с умными помощниками и интерактивными приложениями**, которые работают в чатах, каналах и группах.

**Ключевые принципы:**
- Всё делается **внутри HanWe** — без выхода в браузер или другие приложения
- Создание бота — **просто и быстро** (как через @BotFather)
- Мини-приложения запускаются **внутри HanWe** (WebView) с нативным ощущением
- Выглядит и работает **точно как в Telegram**

**Целевая аудитория внутри HanWe:**
- Обычные пользователи, которые хотят создать бота для своего канала/чата (уведомления, игры, автоматизация)
- Владельцы каналов, которые хотят добавить интерактив (кнопки, мини-игры, формы)
- Пользователи, которые хотят пользоваться готовыми ботами HanWe (погода, рецепты, напоминания, игры)

**Ключевые сценарии:**
1. Пользователь открывает **@BotFather** → "Создать бота" → получает токен и username за 30 секунд
2. Пользователь добавляет своего бота в чат/канал → бот отвечает на `/start`
3. В сообщении бота появляется **Inline-кнопка "Открыть калькулятор калорий"** → открывается мини-приложение внутри HanWe
4. Владелец канала публикует пост с кнопкой "Играть" → запускается мини-игра для подписчиков
5. Пользователь находит готовых ботов HanWe в каталоге ("Погода", "Рецепты дня", "Напоминания") и добавляет их в чат

## 📋 Общая архитектура (встроенная в HanWe)

### 1. Боты (Bots)
- Специальный тип пользователя (`users.is_bot = true`)
- Каждый бот имеет `bot_token` и `bot_username`
- Боты создаются **через UI HanWe** (аналог @BotFather)
- Боты могут:
  - Отправлять сообщения, фото, видео, рецепты
  - Отвечать на команды (`/start`, `/help`, кастомные)
  - Показывать Reply и Inline клавиатуры
  - Работать в inline-режиме (`@bot query`)
  - Запускать мини-приложения

### 2. Мини-приложения (Mini Apps) — главный каталог в HanWe
- **Мини-приложения отображаются как отдельный раздел (каталог) в нижней навигации HanWe** — в позиции, аналогичной разделу "Menu" в HAN Eat.
- Это основной способ discovery и запуска мини-приложений для пользователей HanWe.
- Точки входа (дополнительно к каталогу):
  - Inline-кнопка в сообщении бота (`WebApp` button)
  - Attach Menu в чате
  - Кнопка "Мини-приложения" в профиле бота
  - Глубокие ссылки `haneat://miniapp/{bot_id}/{app_path}`
- Доступ к **HanWe WebApp API** (аналог Telegram WebApp):
  - `WebApp.themeParams`, `WebApp.colorScheme`
  - `WebApp.initDataUnsafe` (user, auth_date, hash)
  - `WebApp.sendData()`, `WebApp.close()`, Haptic Feedback, BackButton
  - Безопасная авторизация через HMAC-подпись

### 3. Встроенный BotFather
- Специальный бот **@BotFather** (или раздел "Мои боты" → "Создать бота")
- Через него пользователь:
  - Создаёт нового бота
  - Настраивает имя, описание, аватар
  - Добавляет команды
  - Настраивает webhook (опционально) или использует встроенный обработчик HanWe
  - Управляет правами бота

### 4. Готовые мини-приложения HanWe
- HanWe предоставляет **готовые мини-приложения**:
  - Калькулятор калорий / БЖУ
  - Погода
  - Переводчик
  - Рецепты по ингредиентам
  - Напоминания и todo
  - Мини-игры (угадай рецепт, квиз и т.д.)
- Пользователь может **добавлять свои web-приложения** (URL) к своим ботам

### Фаза 1: Backend — Боты и BotFather (3–4 недели)

#### 1.1. Модель данных

```sql
-- Расширение таблицы users
ALTER TABLE users ADD COLUMN is_bot BOOLEAN DEFAULT FALSE;
ALTER TABLE users ADD COLUMN bot_token VARCHAR(64) UNIQUE;
ALTER TABLE users ADD COLUMN bot_username VARCHAR(32) UNIQUE;
ALTER TABLE users ADD COLUMN bot_description TEXT;
ALTER TABLE users ADD COLUMN bot_short_description VARCHAR(120);
ALTER TABLE users ADD COLUMN bot_avatar_url TEXT;
ALTER TABLE users ADD COLUMN created_by_user_id INTEGER REFERENCES users(id); -- кто создал бота

-- Команды бота
CREATE TABLE bot_commands (
  id SERIAL PRIMARY KEY,
  bot_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  command VARCHAR(32) NOT NULL,
  description VARCHAR(256) NOT NULL,
  UNIQUE(bot_id, command)
);

-- Inline и Reply клавиатуры (хранятся как JSON)
CREATE TABLE bot_keyboards (
  id SERIAL PRIMARY KEY,
  bot_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  keyboard_type VARCHAR(20) NOT NULL, -- 'reply' | 'inline'
  name VARCHAR(64),
  data JSONB NOT NULL -- структура клавиатуры
);

-- Мини-приложения бота
CREATE TABLE bot_miniapps (
  id SERIAL PRIMARY KEY,
  bot_id INTEGER REFERENCES users(id) ON DELETE CASCADE,
  name VARCHAR(64) NOT NULL,
  short_name VARCHAR(32) NOT NULL,
  url TEXT NOT NULL, -- внешний URL или встроенный HanWe miniapp
  is_builtin BOOLEAN DEFAULT FALSE, -- true = готовое мини-приложение HanWe
  icon_url TEXT
);
```

#### 1.2. Встроенный BotFather — API

```
POST   /api/v1/bots/create
       Body: { name, username, description? }
       → { bot_token, bot_user_id, bot_username }

GET    /api/v1/bots/my          # список ботов текущего пользователя
GET    /api/v1/bots/{bot_id}
PUT    /api/v1/bots/{bot_id}
DELETE /api/v1/bots/{bot_id}

POST   /api/v1/bots/{bot_id}/commands
GET    /api/v1/bots/{bot_id}/commands
DELETE /api/v1/bots/{bot_id}/commands/{command_id}

POST   /api/v1/bots/{bot_id}/miniapps
GET    /api/v1/bots/{bot_id}/miniapps
```

#### 1.3. Обработка сообщений ботов (внутренний движок)

- Бот **не требует webhook** от пользователя
- HanWe имеет **встроенный обработчик**:
  - При получении сообщения в чат с ботом → HanWe обрабатывает команду
  - Если команда `/start` → бот отвечает приветствием
  - Если команда из `bot_commands` → бот отвечает описанием
  - Inline-режим: `@bot query` → поиск по командам или мини-приложениям

#### 1.4. Базовый набор команд (по умолчанию у каждого бота)
- `/start` — приветствие
- `/help` — список команд
- Пользователь может добавлять свои команды через BotFather

#### 1.5. Отправка сообщений от бота

```
POST   /api/v1/bots/{bot_id}/sendMessage
       Body: { chat_id, text, reply_markup?, parse_mode? }

POST   /api/v1/bots/{bot_id}/sendPhoto
POST   /api/v1/bots/{bot_id}/sendRecipe (специфично для HanWe)
```

### Фаза 2: Клиент — Интеграция ботов в HanWe (3 недели)

#### 2.1. Экран "Мои боты" (BotFather)
- Список созданных ботов
- Кнопка "Создать бота" → открывает flow BotFather
- Для каждого бота:
  - Редактировать имя/описание/аватар
  - Добавить/удалить команды
  - Добавить мини-приложение
  - Удалить бота

#### 2.2. Отображение ботов в чатах и каналах
- Специальный аватар + badge "бот"
- В профиле бота — кнопки:
  - "Начать чат"
  - "Добавить в чат/канал"
  - "Открыть мини-приложения"

#### 2.3. Клавиатуры (Reply и Inline)
- **ReplyKeyboardMarkup** — отображается под полем ввода
- **InlineKeyboardMarkup** — кнопки под сообщением:
  - `callback_data` → отправка `answerCallbackQuery` + обновление сообщения
  - `web_app` → запуск мини-приложения
  - `url` → внешняя ссылка
  - `switch_inline_query` → inline-режим

#### 2.4. Inline-режим
- При вводе `@botname query` в любом чате:
  - Показывать результаты (команды, мини-приложения, быстрые ответы)
  - Выбор результата → бот отправляет сообщение или запускает мини-приложение

#### 2.5. Добавление бота в чат/канал
- Пользователь выбирает чат/канал
- Бот присоединяется с правами (может читать/писать сообщения)
- Владелец чата может удалить бота

### Фаза 3: Мини-приложения внутри HanWe (4 недели)

#### 3.1. Готовые мини-приложения HanWe (встроенные)

HanWe предоставляет готовые мини-приложения:

| Мини-приложение       | Описание                        | Доступность     |
|-----------------------|---------------------------------|-----------------|
| Калькулятор калорий   | Считает БЖУ и калории           | Все пользователи |
| Погода                | Погода по городу                | Все пользователи |
| Рецепты по фото       | Распознаёт ингредиенты          | Все пользователи |
| Переводчик            | Перевод текста                  | Все пользователи |
| Напоминания           | Todo и reminders                | Все пользователи |
| Мини-игра "Угадай рецепт" | Квиз на знание рецептов     | Все пользователи |

#### 3.2. WebApp Bridge (JavaScript)

```js
// window.HanWe.WebApp (аналог window.Telegram.WebApp)
const WebApp = window.HanWe.WebApp;

WebApp.ready();
WebApp.expand();
WebApp.close();
WebApp.sendData(JSON.stringify({action: 'buy', item: 42}));
WebApp.showAlert('Спасибо!');
WebApp.hapticFeedback('success');

const initData = WebApp.initDataUnsafe; // {user, auth_date, hash, start_param}
```

#### 3.3. Flutter WebView Integration

- Пакет: `flutter_inappwebview`
- Инъекция `window.HanWe.WebApp` объекта
- Передача `initData` с HMAC-подписью
- Поддержка:
  - Theme sync (цвета из Material 3)
  - Safe Area + Bottom Bar padding
  - BackButton handling
  - Haptic feedback
  - Biometric (опционально)

#### 3.4. Запуск мини-приложения

- Из Inline-кнопки в сообщении бота
- Из Attach Menu в чате
- Из профиля бота
- Из каталога мини-приложений

#### 3.5. Добавление своего мини-приложения

- Владелец бота может добавить **своё web-приложение**:
  - Указать URL
  - Указать short_name (для ссылки)
  - Мини-приложение появляется в InlineKeyboard и Attach Menu

#### 3.6. Безопасность

- Origin whitelist для каждого мини-приложения
- Проверка HMAC-подписи `initData`
- CSP + sandbox для WebView

## 🛠️ Технические решения

### Backend
- **Встроенный обработчик ботов** (не требует webhook от пользователя)
- **Webhook (опционально)** — для продвинутых ботов (владелец бота может указать свой URL)
- **HMAC-подпись** для `initData` мини-приложений
- **Rate limiting** на сообщения ботов

### Flutter
- `flutter_inappwebview` — для мини-приложений
- Новые провайдеры:
  - `bot_provider.dart`
  - `miniapp_launcher_provider.dart`
  - `webapp_bridge.dart`

### Новые таблицы БД
- `bot_commands`
- `bot_keyboards`
- `bot_miniapps`
- `bot_permissions`
- `miniapp_launches` (аналитика)
